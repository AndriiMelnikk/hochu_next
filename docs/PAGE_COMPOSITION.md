# Композиція сторінок Shukayu

Які **блоки** стоять на головних екранах і як вони складаються. Принцип розкладки — як на Upwork: оболонка + одна головна колонка + вузька права рейка (де вона потрібна). Не копія їхніх секцій 1:1.

Візуал блоків — [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md).  
Поведінка контролів — [`UX_COMPONENTS.md`](UX_COMPONENTS.md).  
Цей файл не задає px/кольори і не розписує бізнес-правила API.

Маршрути — поточні з `src/app/router/routes.ts`. Де цільова композиція відрізняється від коду зараз — позначено **(ціль)**.

---

## 1. Дві оболонки

| Оболонка | Де | Склад |
|---|---|---|
| **Public** | гість: `/`, how-it-works, about, blog, login, register, pricing, legal | Хедер 64px + `main` + футер |
| **Cabinet** | авторизований: стрічка запитів, деталі запиту/пропозиції, свій профіль, налаштування, створення запиту | Icon-rail 64px + `main` без публічного футера (або компактний футер-лінки внизу контенту) |

**(ціль)** Гість на `/` бачить Public. Після логіну `/` стає кабінетною стрічкою (як Find work на Upwork), а маркетинговий лендінг лишається для гостя. `/request` завжди стрічка — той самий каркас, щоб URL можна було шерити.

На `&lt; lg` cabinet-rail → bottom nav або burger + Sheet (див. дизайн-систему §6).

## 2. Словник блоків

Повторювані цеглини. Сторінки нижче лише збирають їх.

| Блок | Що всередині | Upwork-аналог |
|---|---|---|

| **AccountMenu** | шапка (ім’я, тип профілю), Switch «онлайн», пункти, Switch accounts, вихід | меню аватара |
| **Greeting** | дата + «Доброго ранку, {ім’я}» | хедер Find work |
| **SearchBar** | одне поле пошуку на всю ширину колонки | search jobs |
| **FeedTabs** | Best matches / Найновіші / Збережені / Запрошення (якщо є) + кнопка Filters | Best matches / Most recent / Saved / Invites |
| **ListingCard** | бейджі, заголовок, мета, опис 3 рядки + more, чіпи категорій, футер (бюджет, локація, пропозиції) | job card |
| **FeedList** | вертикальний стек ListingCard, gap 16px, пагінація знизу | стрічка вакансій |

| **StickyCta** | primary + outline, липне під час скролу основної колонки на `lg+` | Apply now / Save job |
| **EntityHeader** | H1, мета-рядок (дата, локація, статус), без CTA (CTA в рейці) | заголовок джоби |
| **EntityBody** | секції з H2: опис, вимоги, вкладення, скіли/категорії, активність | Summary / Skills / Activity |
| **AboutCounterparty** | аватар, ім’я, рейтинг, локація, статистика угод | About the client |
| **PromoBanner** | soft-картка, dismiss, одна текстова дія | Upgrade / Share talent |
| **ProfileIdentity** | аватар, ім’я, верифікація, локація, час, title, ставка/роль, кнопки | шапка профілю |
| **SectionCard** | біла картка, H2, контент, опційний edit-олівець | Overview / Portfolio |
| **FormCanvas** | вузька колонка форми (~640–720px) по центру або ліворуч + підказки справа | post a job |

Права рейка **300–320px**. Основна колонка забирає решту, max контенту кабінету ~1120px.

## 3. Головна `/` (гість) — лендінг

**Оболонка:** Public.  
**Мета:** пояснити продукт і дати дві дії — створити запит або дивитись запити.

```
TopNav
┌─────────────────────────────────────────────┐
│  HERO                                        │
│  H1 + підзаголовок                           │
│  [Пошук запитів ............] [Шукати]       │
│  [Створити запит]  [Дивитись запити]         │
│  (пошук важливіший за сітку статистик)       │
└─────────────────────────────────────────────┘
Категорії (чіпи-посилання, 8–12 шт.)
Останні запити — 3–6 ListingCard, CTA «Усі запити»
Як це працює — 3 кроки в ряд
Довіра / гарантії (коротко)
FAQ (Accordion)
Footer
```

**Блоки зверху вниз:**

1. **TopNav** — лого, Запити, Як це працює, мова, Увійти outline, Реєстрація primary.
2. **Hero** — H1, 1 абзац, **пошук** (як на лендінгу Upwork), під ним два CTA: primary «Створити запит», outline «Дивитись запити». Сітку з 4 статистичних карток прибрати з hero або звести до одного рядка benefit (без карток).
3. **Категорії** — горизонтальні чіпи, ведуть на `/request?category=`.
4. **LatestRequests** — заголовок секції + FeedList на 3–6 карток + link «Дивитись усі». Не окремий стиль карток: той самий ListingCard.
5. **How it works** — 3 кроки (створив запит → отримав пропозиції → обрав). Не більше однієї секції «features».
6. **FAQ** — Accordion single.
7. **Footer** — 4 колонки як зараз (бренд, платформа, компанія, legal).

**Не класти на лендінг:** icon-rail, особистий greeting, фільтри кабінету, повний лістинг з пагінацією.

## 4. Стрічка запитів `/request` (і `/` для авторизованого)

**Оболонка:** Cabinet якщо залогінений, Public якщо гість (без RightRail профілю).  
**Мета:** сканувати запити й відкрити деталі — як Find work.

```
IconRail │  Greeting (auth)              │ RightRail
         │  SearchBar                    │  • Картка профілю
         │  FeedTabs + Filters           │    (аватар, title, повнота)
         │  ─ ListingCard                │  • PromoBanner
         │  ─ ListingCard                │  • Преференції / підписка
         │  ─ …                          │
         │  Pagination                   │
```

**Ліва колонка:**

1. **Greeting** (лише auth) — дата + ім’я. Без цього для гостя: H1 «Запити».
2. **SearchBar** — одне поле, debounce, не всередині важкої сірої картки-форми.
3. **FeedTabs** — Найкращі / Найновіші / Збережені / Запрошення. Гість бачить лише Найновіші (інші таби — login wall за UX: disabled + tooltip або редірект на login).
4. **Filters** — кнопка outline справа від табів → Sheet/Popover: категорія (CascadingSelect), місто, бюджет, терміновість. Активні фільтри — чіпи під табами, можна зняти.
5. **FeedList** — ListingCard на всю ширину колонки (не сітка 2–3 плиток). Картка = посилання на `/request/[id]`.
6. **Pagination** — під списком, не infinite scroll.

**Права рейка (`lg+`, auth):**

1. Повнота профілю + лінк «Дозаповнити» (Progress).
2. PromoBanner (dismissible).
3. Преференції / підписка на нові запити (коротко) або «Створити запит» outline.

На `&lt; lg` рейка ховається: повнота профілю — компактний рядок під Greeting; фільтри — Sheet.

**Не класти:** героїчний H1 з градієнтом, велика картка «пошук+фільтри» окремим блоком над усім, статистика платформи.

## 5. Деталі запиту `/request/[id]`

**Оболонка:** Cabinet (auth) або Public (гість).  
**Мета:** зрозуміти задачу й виконати одну дію (пропозиція / відгук / редагування свого запиту).

```
IconRail │  Breadcrumbs                     │ StickyCta
         │  EntityHeader (H1, мета)         │  [Надіслати пропозицію]
         │  EntityBody                      │  [Зберегти]
         │    Summary                       │  Flag / поділитися
         │    Умови (бюджет, строк, місто)  │  ─ AboutCounterparty
         │    Категорії / скіли (чіпи)      │  ─ Активність
         │    Вкладення                     │     (N пропозицій…)
         │    «more» довгого тексту         │
         │  Tabs: Пропозиції | Обговорення  │
```

**Основна колонка:**

1. **Breadcrumbs** — головна / категорія / поточний заголовок.
2. **EntityHeader** — H1, дата, локація, статус-бейдж. Без гігантських CTA в шапці.
3. **EntityBody** — секції з H2, роздільники 1px. Довгий опис — 3 рядки + more.
4. **Чіпи** категорій/навичок — обов’язковий блок перед активністю.
5. **Tabs** — Пропозиції | Обговорення (для власника; для виконавця обговорення за правилами доступу). Форма пропозиції **не** посеред статті: або в рейці (почати), або якір «до форми» після кліку CTA.

**Права рейка (липка):**

1. **StickyCta**
   - виконавець: primary «Надіслати пропозицію», outline «Зберегти»;
   - власник: outline «Редагувати», destructiveOutline «Скасувати запит» у ⋯ меню, не два primary;
   - гість: primary «Увійти, щоб відгукнутись».
2. Підказка вартості дії, якщо з’явиться (аналог Connects) — текст 12–14px muted, не окрема драма.
3. **AboutCounterparty** — замовник: аватар, ім’я, рейтинг, місто, угод, верифікація. Клік на ім’я → публічний профіль.
4. Активність: кількість пропозицій, переглядів, інвайтів — компактний список, не велика цифра в hero-картці.

На мобільному StickyCta → **липкий бар знизу** (над bottom nav, якщо він є). AboutCounterparty їде під EntityBody.

Форма створення пропозиції після CTA: Dialog на desktop або Sheet на mobile **або** якір у основній колонці під табами — один патерн на проєкт (рекомендовано: Sheet/Dialog, щоб не розривати читання).

**Не класти:** дубль CTA в шапці й у рейці одночасно; форма пропозиції між заголовком і описом.

## 6. Свій профіль `/profile` і `/profile/[id]` (власник)

**Оболонка:** Cabinet.  
**Мета:** керувати публічним виглядом і своїми сутностями, не змішувати з «налаштуваннями акаунта».

```
IconRail │  ProfileIdentity     [Дивитись як гість] [Налаштування]
         │  PromoBanner (опційно)
         │  Title + ставка/роль + короткий tagline
         │  Overview (SectionCard, more)
         │  Tabs: Огляд | Портфоліо | Відгуки | Запити
         │  контент таба
```

**Блоки:**

1. **ProfileIdentity** — аватар, онлайн-крапка, ім’я, Verify як текстове посилання (не окремий hero), локація + локальний час.
2. Дві кнопки справа: outline «Публічний вигляд», primary ghost/олівець → редагування title **або** лінк у Settings. Як на Upwork: не ховати edit у табах.
3. **Title** (H1 секції) — спеціалізація, не ім’я повторно. Поруч ставка або тип профілю (покупець/продавець).
4. **Overview** — 3 рядки + more.
5. **Tabs** (підкреслення, не сегмент):
   - власник: Огляд (запити/пропозиції + статистика), Портфоліо (якщо продавець), Відгуки, Запити/Пропозиції;
   - гейміфікацію не робити окремим табом першого рівня — компактний Progress у RightRail або в Огляді.
6. ListingCard / таблиця сутностей всередині таба — той самий каркас, що стрічка.

**Права рейка (опційно):** повнота профілю, перемикач профілю buyer/seller (короткий), PromoBanner. Якщо рейка порожня — не малювати порожню колонку.

Повідомлення й чат **не** є табами профілю **(ціль)**: вони — пункти IconRail (окремі екрани). Зараз чат/нотифікації сидять у табах профілю — при редизайні винести.

## 7. Публічний профіль `/profile/[id]` (гість / інший користувач)

**Оболонка:** Public або Cabinet (якщо глядач залогінений).  
**Мета:** довіра й контакт, без чужих налаштувань.

```
ProfileIdentity (без «Налаштування», без email)
Overview
Чіпи спеціалізацій
Портфоліо / виконані кейси (ListingCard або галерея)
Відгуки
StickyCta справа: «Написати» / «Запросити» за роллю
```

Таби лише: Огляд | Портфоліо | Відгуки. Без notifications, settings, profiles, chat.

## 8. Налаштування **(ціль:** окремий екран, зараз таб `#settings`)

**Оболонка:** Cabinet.  
**Маршрут (ціль):** `/profile/[id]#settings` можна лишити, але layout як окрема сторінка Settings, не «ще один таб серед огляду». Краще `/settings` з лівим списком секцій.

```
IconRail │  H1 Налаштування
         │  ┌──────────┬─────────────────────┐
         │  │ Секції   │  SectionCard        │
         │  │ Профіль  │  форма / світчі     │
         │  │ Контакти │                     │
         │  │ Нотифік. │                     │
         │  │ Безпека  │                     │
         │  │ Профілі  │                     │
         │  └──────────┴─────────────────────┘
```

**Секції (лівий список на `md+`, Accordion/Sheet на мобільному):**

1. **Профіль** — ім’я, аватар, title, про себе, локація, видимість (Public/Private).
2. **Контакти** — канали зв’язку (обов’язкові для пропозиції).
3. **Сповіщення** — Switch-рядки (як «Online for messages»): email / in-app по типах. Без окремої кнопки Save на кожен Switch.
4. **Безпека** — зміна пароля (Dialog), сесії, вихід (destructiveOutline, не primary).
5. **Профілі** — buyer/seller switcher, створення профілю.
6. **Верифікація** — якщо ще не готово: SectionCard disabled + підпис «пізніше», не порожня діра.

Не змішувати лістинг запитів і редагування пароля на одному скролі без навігації секцій.

AccountMenu веде сюди пунктом «Налаштування». «Дивитись публічний профіль» — окремий пункт/кнопка в Identity, не всередині форм.

## 9. Створення запиту `/create`

**Оболонка:** Cabinet (auth required; гість → login з returnUrl).  
**Мета:** одне полотно форми, без стрічки й hero.

```
IconRail │  H1 Новий запит
         │  FormCanvas (поля групами)
         │    Основне: назва, категорія, опис
         │    Умови: бюджет, місто, терміновість
         │    Вкладення
         │  [Скасувати] [Опублікувати]
         │                    RightRail: короткі підказки «як написати»
```

Групи полів — SectionCard або H2 + gap 16px, не одна суцільна простирадла без якорів. Sticky footer з CTA на мобільному.

Після успіху → `/request/[id]`, не назад на лендінг.

## 10. Вхід і реєстрація `/login`, `/register`

**Оболонка:** Public, **без** повного футера або з мінімальним. Центрований canvas.

**Реєстрація (ціль, як Upwork welcome):**

```
Лого
H1 «Ласкаво просимо»
Дві картки: Замовник | Виконавець
«Вже є акаунт? Увійти»
```

Після вибору ролі — форма (email/пароль/Google) на тому ж екрані або наступний крок. Не ховати вибір ролі внизу довгої форми.

**Логін:** картка по центру, поля, Google, лінки forgot + register. Без стрічки запитів на фоні.

## 11. Сповіщення (ціль: екран IconRail, зараз таб профілю)

**Оболонка:** Cabinet.

```
H1  Tabs: Активність | Підписки
Список рядків (іконка, текст, час, dismiss)
Порожній стан, якщо немає подій
```

Фільтри — як зараз (unread, category, scope), компактний рядок над списком, не картка-колос. Пагінація.

Не дублювати цей список у dropdown дзвіночка повністю: дзвіночок = 5 останніх + «Дивитись усі».

## 12. Деталі пропозиції `/proposal/[id]`

Той самий каркас, що деталі запиту: EntityHeader + Body + StickyCta + AboutCounterparty (тепер виконавець або замовник залежно від глядача). Таби: Деталі | Обговорення | Статус угоди. Не винаходити третю сітку.
